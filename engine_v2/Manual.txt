UPDATED MANUAL: ENSEMBLE RECOMMENDATION MODEL (SINGLE‑TRACK)
============================================================

This document explains how to load the trained model, serve
a single personalised track recommendation per request, handle
cold‑start users, instantly update a user’s profile, and
gracefully handle cases where the primary artists are exhausted.
All model files are in the "model_params" folder.

------------------------------------------------------------
1. PREREQUISITES
------------------------------------------------------------

- Python 3.8+
- PyTorch, NumPy, pandas, scikit‑learn
- Standard libraries: pickle, json, collections

model_params/

  user_enc_artist.pkl             – LabelEncoder: user_id -> index (artist model)
  artist_enc.pkl                 – LabelEncoder: canonical artist_id -> index

  track_model_state.pt           – (optional) state dict of TrackMF
  genre_features.pt              – (optional) aligned genre matrix
  artist_user_embeddings.npy     – precomputed user embeddings (artist model)
  artist_artist_embeddings.npy   – precomputed artist embeddings (artist model)
  track_user_embeddings.npy      – precomputed user embeddings (track model)
  track_item_embeddings.npy      – precomputed item (track) embeddings

We will use the precomputed .npy files for speed. The optional
files are only needed if you want to reload the full models.

3. MODEL CLASS DEFINITIONS (must match training code)

import torch.nn as nn

class HybridArtistMF(nn.Module):
    def __init__(self, n_users, n_artists, emb_dim, genre_dim):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, emb_dim)
        self.artist_id_emb = nn.Embedding(n_artists, emb_dim)
        self.genre_proj = nn.Linear(genre_dim, emb_dim, bias=False)
        self.user_bias = nn.Embedding(n_users, 1)
        self.artist_bias = nn.Embedding(n_artists, 1)

    def forward(self, user_idx, artist_idx, genre_features):
        u = self.user_emb(user_idx)
        a_id = self.artist_id_emb(artist_idx)
        a_genre = self.genre_proj(genre_features[artist_idx])
        a = a_id + a_genre
        dot = (u * a).sum(dim=-1)
        u_bias = self.user_bias(user_idx).squeeze(-1)
        a_bias = self.artist_bias(artist_idx).squeeze(-1)
        return dot + u_bias + a_bias

class TrackMF(nn.Module):
    def __init__(self, n_users, n_items, emb_dim):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, emb_dim)
        self.item_emb = nn.Embedding(n_items, emb_dim)

    def forward(self, user, item):
        u = self.user_emb(user)
        i = self.item_emb(item)
        return (u * i).sum(dim=-1)

# Serving parameters (RECOMMENDED)
N_ARTISTS = 5                 # top artists to consider

5. RECOMMENDATION FOR A KNOWN USER (single track, with exhaustion fallback)
------------------------------------------------------------

def recommend_for_user(user_id, seen_tracks=None):
    """
    user_id: original user ID (integer or string)
    seen_tracks: set of track IDs the user already interacted with
                 (liked, disliked, uploaded) or previously recommended.
    Returns a single track ID or None if nothing can be found.
    """
    if seen_tracks is None:
        seen_tracks = set()

    # Quick check: if user not in artist model, fallback to global popular unseen
    if user_id not in user_id_to_idx_artist:
        return get_popular_unseen(seen_tracks, n=1)

    u_idx_artist = user_id_to_idx_artist[user_id]
    user_vec = artist_user_emb[u_idx_artist]

    # Attempt with configured artist count, then expand if needed
    for attempt, multiplier in enumerate([1, 2, 5, 10]):  # progressively widen the search
        n_art = min(N_ARTISTS * multiplier, len(artist_enc.classes_))
        # Artist ranking
        scores = user_vec.dot(artist_artist_emb.T)
        top_artists = np.argpartition(scores, -n_art)[-n_art:]
        top_artists = top_artists[np.argsort(scores[top_artists])[::-1]]

        candidates = set()
        for aidx in top_artists:
            artist_tracks = [t for t in artist_to_tracks.get(aidx, [])
                             if t not in seen_tracks]
            if not artist_tracks:
                continue
            # Pick top TRACKS_PER_ARTIST by popularity (or all if fewer)
            artist_tracks_sorted = sorted(artist_tracks,
                                          key=lambda t: track_pop[track_id_to_idx.get(t, -1)]
                                          if t in track_id_to_idx else 0,
                                          reverse=True)
            for t in artist_tracks_sorted[:TRACKS_PER_ARTIST]:
                candidates.add(t)

        if candidates:
            break   # we found something
    else:
        # All artists exhausted, fall back to globally popular unseen tracks
        return get_popular_unseen(seen_tracks, n=1)

    # Re‑rank with track model (if available)
    if USE_ENSEMBLE and user_id in user_id_to_idx_track:
        u_idx_track = user_id_to_idx_track[user_id]
        u_vec_track = track_user_emb[u_idx_track]
        scored = []
        for tid in candidates:
            if tid in track_id_to_track_idx:
                i_idx = track_id_to_track_idx[tid]
                s = np.dot(u_vec_track, track_item_emb[i_idx])
                scored.append((tid, s))
        scored.sort(key=lambda x: x[1], reverse=True)
        best_track = scored[0][0] if scored else None
    else:
        best_track = max(candidates,
                         key=lambda t: track_pop[track_id_to_idx.get(t, -1)]
                         if t in track_id_to_idx else 0)

    return best_track

def get_popular_unseen(seen_tracks, n=1):
    """Return the globally most popular unseen tracks."""
    all_tracks = sorted(track_id_to_idx.keys(),
                        key=lambda t: track_pop[track_id_to_idx[t]],
                        reverse=True)
    for t in all_tracks:
        if t not in seen_tracks:
            return t
    return None

6. COLD‑START FOR A NEW USER
------------------------------------------------------------

A new user has no internal embedding. The bot should:

  a) Present 5 onboarding tracks (diverse popular tracks from different
     popular artists).  Keep their track IDs.
  b) Wait for the user to react with a positive emoji (score > 1.0).
  c) For each reacted track, obtain its primary artist via
     track_to_artist.  Collect the unique artist IDs.
  d) Build a temporary user vector from those artists:

     reacted_artists = set()
     for tid in reacted_track_ids:
         aid = track_to_artist.get(tid)
         if aid and aid in artist_enc.classes_:
             reacted_artists.add(aid)

     artist_indices = [artist_enc.transform([a])[0] for a in reacted_artists]
     if not artist_indices:
         # fallback: recommend globally popular unseen track
         return get_popular_unseen(seen_tracks, n=1)

     user_vec = np.mean(artist_artist_emb[artist_indices], axis=0)

  e) Use the same candidate collection logic as in recommend_for_user,
     but with this user_vec.  Since the user has no track‑model embedding,
     the track re‑ranking is skipped; candidates are sorted by popularity.
     The "seen_tracks" set must include the onboarding tracks.

After this, the user immediately gets a personalised recommendation.

------------------------------------------------------------
7. UPDATING THE MODEL FOR A SINGLE USER (NO RETRAINING)
------------------------------------------------------------

When a user reacts to a new track, update their profile instantly:

For the ARTIST model:
  - Gather all canonical artist IDs the user has ever positively
    interacted with (liked tracks, positive reactions, uploads).
  - Convert to indices via artist_enc.
  - Compute new user vector:
      artist_indices = [artist_enc.transform([a])[0] for a in artist_ids
                        if a in artist_enc.classes_]
      new_user_vec = np.mean(artist_artist_emb[artist_indices], axis=0)
  - Optionally weight by reaction score.

For the TRACK model (used for re‑ranking if the user has enough history):
  - Gather all liked track IDs.
  - Convert to indices and average the track embeddings:
      track_indices = [track_id_to_track_idx[t] for t in liked_track_ids
                       if t in track_id_to_track_idx]
      new_track_vec = np.mean(track_item_emb[track_indices], axis=0)

These operations take < 1 ms and can be performed on every
/recommend call.  The bot never needs to retrain.

------------------------------------------------------------
8. INTEGRATION TIPS
------------------------------------------------------------

- Keep a per‑user "seen_tracks" set in your database.  Add every
  track the user has liked, disliked, uploaded, or been recommended.
  This prevents repeats.

- Onboarding tracks: pre‑compute a list of 5 tracks from 5 different
  top artists (e.g., the tracks with highest track_pop from the 5 most
  popular artists).  Refresh this list when the model is retrained.

- The fallback in recommend_for_user automatically broadens the
  artist pool if the top artists are exhausted, finally falling back
  to globally popular unseen tracks.  You can adjust the multipliers
  [1, 2, 5, 10] to suit your needs.

- The recommended serving parameters (N_ARTISTS=5, TRACKS_PER_ARTIST=1,
  ENSEMBLE=True) were chosen because:
    * They provide reliable recommendations for all users (no exhaustion).
    * They offer artist variety while keeping Recall@1 at ~0.038 (strong
      for this sparse dataset).
    * Using fewer artists (e.g., 1) gave slightly higher recall but frequently
      ran out of tracks and created an echo chamber.  Using more artists or
      tracks per artist lowered recall.

- The entire pipeline runs in < 10 ms on CPU.

------------------------------------------------------------
9. PERFORMANCE NOTES
------------------------------------------------------------

- All operations are pure NumPy/Python and run on CPU.
- The artist ranking involves a dot product of (1, 200) x
  (200, N_artists) – negligible.
- Candidate collection is dictionary lookups.
- No GPU is needed for serving.
