 MODEL LOADING AND INFERENCE GUIDE (server guy)
============================================================

All files are located in the /model_params directory.
You need Python 3.8+, PyTorch, NumPy, pandas, scikit-learn,
and pickle (standard lib). No GPU is required; CPU is fine.

------------------------------------------------------------
1. Load the model and associated data
------------------------------------------------------------

- Read config.json to get embedding_dim, n_users, n_artists,
  top_k, n_artists_rec, tracks_per_artist.

- Instantiate the exact same MF model class (see below) with
  (n_users, n_artists, embedding_dim).

- Load the state dict:
      state = torch.load('model_params/model_state.pt',
                         map_location='cpu')
      model.load_state_dict(state)
      model.eval()

- Load the other files:
      user_enc    = pickle.load(open('model_params/user_enc.pkl','rb'))

      track_to_artist = pickle.load(open('model_params/track_to_artist.pkl','rb'))
      track_id_to_idx = pickle.load(open('model_params/track_id_to_idx.pkl','rb'))
      track_pop   = np.load('model_params/track_pop.npy')

- Also load your tracks metadata (tracks.csv) for displaying

------------------------------------------------------------
2. The MF model class (must match training code exactly)
------------------------------------------------------------

class MF(nn.Module):
    def __init__(self, n_users, n_items, emb_dim):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, emb_dim)
        self.item_emb = nn.Embedding(n_items, emb_dim)
        nn.init.xavier_uniform_(self.user_emb.weight)
        nn.init.xavier_uniform_(self.item_emb.weight)

    def forward(self, user, item):
        u = self.user_emb(user)
        i = self.item_emb(item)
        return (u * i).sum(dim=-1)

------------------------------------------------------------
3. Helper: build user vector
------------------------------------------------------------

For a known user with user_id uid:
    - Get the list of artists they have POSITIVELY interacted
      with (energy > threshold). Use the same threshold as in
      training (probably 1.0).
    - For each artist_id, convert to index via
      artist_enc.transform([artist_id])[0].
    - Average the corresponding rows of artist_emb to get a
      single user vector.

If the user is new (cold start):
    - After they react to at least one onboarding track,
      determine the track's primary artist from
      track_to_artist.
    - Average the artist embeddings of all such artists
      (one per reacted onboarding track). That becomes the
      temporary user vector.

------------------------------------------------------------
4. Recommendation pipeline
------------------------------------------------------------

Given a user vector (as a NumPy array of shape (emb_dim,)):

  a. scores = user_vector @ artist_emb.T        # (n_artists,)
  b. Take the indices of the top N = n_artists_rec artists
     (default 5).
  c. For each of those artist indices, convert back to
     original artist ID via artist_enc.inverse_transform.
  d. Find all track_ids belonging to that artist using
     track_to_artist (the dict maps track_id -> artist_id).
  e. For each candidate track, check if the user has already
     seen it (the bot must maintain a per‑user seen_tracks
     set). Exclude any seen tracks.
  f. Look up the track's popularity in track_pop using
     track_id_to_idx to map track_id -> array index.
  g. For each artist, keep the top 'tracks_per_artist' (5)
     tracks sorted by popularity.
  h. Combine tracks from all top artists, deduplicate, sort
     by popularity, and return the top K (10) track IDs.

------------------------------------------------------------
5. Cold‑start details
------------------------------------------------------------

- When a new user starts, send them 5 onboarding tracks.
  Pre‑choose these from popular artists (e.g., the artists
  with the highest total track_pop across their tracks).
  Ensure the 5 tracks are from 5 different artists.
- Store the track IDs of the onboarding session so they can
  be marked as seen.
- Once the user reacts positively to at least one track,
  build the user vector as described (using the primary
  artist of each reacted track) and run the recommendation
  pipeline.
- The bot can then present the 10 recommended tracks.

------------------------------------------------------------
6. Integration with the bot
------------------------------------------------------------

- The bot needs a database table storing for each user:
    - user_id
    - set of seen track IDs
    - (optionally) list of positively reacted artist IDs
      for quick user vector construction.
- On /recommend command:
    - Build user vector (from stored artist list or cold‑start).
    - Run pipeline → get 10 track IDs.
    - Look up track_name and artist_name from your tracks
      table for display.
    - Return the list to the user.

------------------------------------------------------------
7. Performance notes
------------------------------------------------------------

- No retraining is needed on the server; the model files
  are static until the next weekly update.
- The only dynamic data is the per‑user seen set, which
  grows as users interact.
